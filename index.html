PowerShell script for Windows

Application log errors, in a report you can search.

Get-AppEventReport.ps1 reads the Error and Warning events from Event Viewer > Windows Logs > Application for any date range, then writes an interactive HTML report, an Excel file and a CSV.

Quick start

From download to report in seven steps

You need Windows 10 or 11 (or Windows Server 2016 and later) and the PowerShell that ships with it. A normal user account can usually read the Application log. Excel and an internet connection are not required.

  1. Get the project

    Clone the repository with Git. The script is Get-AppEventReport.ps1 in the top folder.

    git clone https://github.com/muhamaddarulhadi/Application-Logs-Viewer.git C:\Scripts\Application-Logs-Viewer

    No Git? Use Code > Download ZIP on the GitHub page and extract it to C:\Scripts\Application-Logs-Viewer.

  2. Open PowerShell

    Open the Start menu, type PowerShell and press Enter. Run it as Administrator only if you later get an access error.

  3. Go to the script folder

    cd C:\Scripts\Application-Logs-Viewer

  4. Allow the script for this window

    Windows may refuse to run scripts. This command lifts the restriction for the current PowerShell window only and resets when you close it.

    Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

    If you downloaded the file, also remove the "downloaded from the internet" flag once:

    Unblock-File .\Get-AppEventReport.ps1

  5. Run the script

    .\Get-AppEventReport.ps1

  6. Enter the dates

    The script asks for a start and an end date. Press Enter to accept the default shown in brackets: seven days ago for the start, today for the end. A date without a time covers the whole day.

  7. Open the report

    The HTML report opens in your browser and the three file locations are printed in the console. Files go to Desktop\EventReports unless you choose another folder.

Reference

      
Parameters

      
If you pass both dates the script runs without any prompt, which is what you want for scheduled tasks.


      

        

          
ParameterTypeDefaultWhat it does

          
            
-StartDatedatePrompted, 7 days agoFirst day to include. Accepts 2026-10-01, 10/01/2026 or a date with time such as "2026-10-01 08:00".

            
-EndDatedatePrompted, todayLast day to include. A date without a time covers the whole day. It must not be earlier than -StartDate.

            
-OutputFolderpathDesktop\EventReportsWhere the HTML, CSV and XLSX files are saved. Created if missing.

            
-IncludeCriticalswitchOffAlso collect Critical events. By default only Error and Warning are collected.

            
-OpenReportswitchOffOpen the HTML report in your browser when done. It also opens if you were prompted for dates.

Output

      
Three files per run

      
Each file name carries a timestamp, so a new run never overwrites an old one. They are saved in -OutputFolder.


      
    
        
  • .html
    The interactive report
    AppEvents_YYYYMMDD_HHMMSS.html is one self-contained file. Email it or open it on any machine, no internet needed.
    • 
        
  • .xlsx
    Excel workbook
    AppEvents_YYYYMMDD_HHMMSS.xlsx holds every event found in the date range, with a colored header, filter buttons and a frozen top row.
    • 
        
  • .csv
    Plain CSV
    AppEvents_YYYYMMDD_HHMMSS.csv has the same data in UTF-8, for scripts and other tools.
    •

The HTML report

      
Find the event, then read its details

      
The report opens with totals and charts, then a table you can search, sort and filter. Click any row to read the full General message.


      

        
    
          
  • Summary and chartsTotals for events, errors, warnings and sources, an events-per-day chart, a severity split and the top sources. Click a source to filter the table to it.
    •

    • 
          
  • Sorting and pagingClick a column header to sort, click again to reverse. Choose 25, 50, 100 or 250 rows per page.
    • 
          
  • Detail panelClick a row to open every field and the full message. Copy copies the message. Previous and Next, or the left and right arrow keys, move between events. Esc closes it.
    • 
          
  • Light and darkThe sun and moon button switches the theme and the report remembers your choice.

Troubleshooting

      
When something does not work

      
Open the line that matches what you see.


      

        "Running scripts is disabled on this system"
        

          
Allow scripts for the current window, then run the script again in the same window.

          
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

        

      

      

        "The file is not digitally signed" or "cannot be loaded"
        

          
The file still carries the downloaded-from-the-internet flag. Remove it once.

          
Unblock-File .\Get-AppEventReport.ps1

        

      

      

        "No errors or warnings found in that date range"
        
The range has no matching events. Try a wider range or add -IncludeCritical. Check that -EndDate is not before -StartDate.

      

      

        Some messages say "(Description unavailable) Raw data"
        
The program that logged the event has no message file installed, often because the app was uninstalled. The report shows the raw event data instead.

      

      

        Access denied, or the log cannot be read
        
Open PowerShell with Run as administrator and try again.

      

      

        The script is slow on a long date range
        
Windows reads the log one record at a time. Use a shorter range or run it when the machine is quiet. Tens of thousands of events can take a minute or more.

      

      

        The report is slow to open in the browser
        
Reports with 50,000 or more events are heavy. Use a narrower date range, or work from the .xlsx or .csv file instead.

      

      

        The Desktop path looks odd, with OneDrive in it
        
That is normal when OneDrive backs up your Desktop. Pick another place with -OutputFolder C:\Reports.

      

      

        A long message is cut off in Excel
        
Excel limits a cell to about 32,000 characters, so the script trims anything longer. The full text is still in the report's detail panel.

      

    


    
    

      
Good to know

      
What the script does and does not touch


      
    
        
  • Windows onlyIt uses Get-WinEvent, which reads the Windows event log.
    • 
        
  • Application log onlySecurity, System and the other logs are not read.
    • 
        
  • Read-onlyIt never changes or clears an event log. It writes only the three report files to the output folder.
    • 
        
  • Local timeDates use the clock of the computer that runs the script.
    • 
        
  • No dependenciesThe .xlsx is built by the script itself, with no Excel, no extra modules and no internet.
    • 
      


      
Run it on a schedule

      
Create a Windows Task Scheduler task with this action. Both dates are passed, so no prompt appears and the report does not open. Use -Command so the (Get-Date) parts are evaluated.

      
powershell.exe -NoProfile -ExecutionPolicy Bypass -Command "& 'C:\Scripts\Application-Logs-Viewer\Get-AppEventReport.ps1' -StartDate (Get-Date).AddDays(-1) -EndDate (Get-Date)"
